# concept-learning —— 七段式概念学习包生成器

## 何时加载

匹配以下任一信号就应加载本 Skill：

- 用户说"系统讲一下 / 深入讲一下 / 给我讲清楚 XXX"
- 用户要求"写一份 XXX 学习资料 / 学习笔记 / 学习手册 / onboarding 文档"
- 用户希望对一个概念形成体系性理解（而不是临时问答）
- 用户要为自己/团队产出**可分享、可复用**的学习材料

**不加载的场景**：

- 临时事实查询（"Python 列表怎么排序"）→ 简短回答
- 代码 bug 调试 → 用 debugging 类 Skill
- 用户已明确表示"随便聊聊" → 走普通对话

## 工作流（七步）

### Step 1 ── 澄清请求

在动笔之前，**先向用户确认**以下 5 项：

| # | 问题 | 默认值 |
|---|------|--------|
| 1 | 目标概念 | 用户输入 |
| 2 | 学习者背景 | 初学者 / 中级 / 资深（**必问**） |
| 3 | 学习深度 | 科普 / 工程应用 / 学术研究 |
| 4 | 输出语言 | 中文（默认） |
| 5 | 输出格式 | Markdown（默认） / HTML / 纯文本 |

> 没有背景与深度，AI 永远会用同一档"半吊子科普"口吻写一切，这是最常见的 AI 学习资料失败模式。

### Step 2 ── 检索权威来源（**硬性环节**）

强制调用 `WebSearch` / `WebFetch` 检索至少 3 类来源：

1. **百科类**：Wikipedia / Britannica
2. **官方文档**：对应技术/学科的官方网站
3. **学术或权威**：arXiv / Google Scholar / 经典教材

把每条 URL 都写下来，**禁止编造**任何 URL、书名、作者、出版年份、论文标题。如果某条事实查不到来源，要么删掉，要么明确标注"未找到公开来源，仅基于常识"。

### Step 3 ── 起草七段式学习包

按下面顺序产出，**不要打乱顺序**：

1. **学习目标（3–5 条）**
   - 用动词开头（能列出、能解释、能比较、能应用、能评估）
   - 对应布鲁姆分类法（详见 `references/bloom-taxonomy.md`）
   - 满足 SMART 原则

2. **核心问题（3–5 个）**
   - 从"是什么"→"为什么"→"怎么用"→"什么时候不该用"
   - 体现作者的认知递进，不是教科书目录的复制

3. **结构化解释**
   - 分层：前置知识 → 核心定义 → 关键机制 → 形式化（可选）
   - **必须体现作者理解**：用你自己的类比、示意图、对比表
   - 不要把整段百科第一段翻译过来

4. **应用案例（≥2 个）**
   - 真实案例（可标注来源）
   - 至少 1 个"踩坑 / 反面案例"

5. **概念辨析（≥1 张对比表）**
   - 与至少 1 个最易混淆的概念对比
   - 用表格而非段落，便于复习

6. **自测题（5–8 题）**
   - 含答案，但答案默认折叠
   - 题型混合：选择 / 简答 / 情境题 / 辨析题
   - 每题标注认知层级（记住 / 理解 / 应用 / 分析）

7. **参考来源（**所有 URL 必须真的可访问**）**
   - 标注 [1] [2] [3]……
   - 每条附"检索日期"
   - **不得**使用"研究表明"、"某权威机构"等模糊归因

### Step 4 ── 真实性核查（交付前必做）

打开每一条参考 URL，确认：

- ✅ 页面可达（不是 404）
- ✅ 内容确实支持正文中的事实陈述
- ✅ 作者、年份、书名拼写正确

把核查日期写在文末：

```
参考来源核查日期：YYYY-MM-DD（使用本文档当天日期）
```

> ⚠️ 如果某条 URL 已失效，立刻换一条或删掉。**绝不**为了凑数留死链。

### Step 5 ── 去 AI 痕迹审查

对照 `references/deai-checklist.md` 逐条扫一遍：

- 删掉"在当今时代"、"作为一个大语言模型"等套话
- 删掉三段式法则堆砌
- 删掉"想象一下，如果..."式空泛开头
- 删掉模糊归因（"研究表明"、"众所周知"）
- 把排比句拆掉或换成有信息密度的句子

### Step 6 ── 输出与归档

- 默认落盘到 `learning-materials/<concept-slug>.md`
- 同时维护一份 `learning-materials/INDEX.md`，按主题归档
- 用户没要求 push 时**不主动** push

### Step 7 ── 收集反馈

交付后问用户：

> 哪一段最有用？哪一段最空泛？要不要补一个"延伸阅读"或"常见误区"？

把反馈记到文件末尾的 `## 修订记录` 区。

## 硬性约束（违反 = 整篇重写）

| # | 约束 |
|---|------|
| ❌ | **禁止伪造**任何 URL、论文标题、作者、年份、出版社 |
| ❌ | **禁止整段照搬** AI 训练数据中的解释而不核查 |
| ❌ | **禁止**使用"研究表明"、"某权威"、"众所周知"等模糊归因 |
| ❌ | **禁止**只写"是什么"不写"为什么"和"什么时候不适用" |
| ✅ | **必须**为每个事实陈述标注来源编号 [1][2]… |
| ✅ | **必须**有学习目标（用动词开头） |
| ✅ | **必须**有自测题（不能只有讲解没有练习） |
| ✅ | **必须**有"核查日期"和"检索日期" |
| ✅ | **必须**体现作者个人理解（自绘类比、原创对比表） |
