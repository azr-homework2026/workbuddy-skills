# concept-learning —— 七段式概念学习包生成器

> 一句话定位：**把"我想懂 XXX"变成一份可核查、可分享、可复习的结构化资料**。

---

## 1. 适用场景

**匹配以下任一信号就应加载本 Skill**：

- 用户说"系统讲一下 / 深入讲一下 / 给我讲清楚 XXX"
- 用户要求"写一份 XXX 学习资料 / 学习笔记 / 学习手册 / onboarding 文档"
- 用户希望对一个概念形成体系性理解（而不是临时问答）
- 用户要为自己/团队产出**可分享、可复用**的学习材料
- 用户的提问落在一个**新概念**上 —— 即 AI 不能仅靠几句"众所周知"打发掉的概念

**不加载的场景**：

- 临时事实查询（"Python 列表怎么排序"）→ 简短回答即可
- 代码 bug 调试 / 报错修复 → 用 debugging 类 Skill
- 用户已明确表示"随便聊聊" / "简单说一下" → 走普通对话

**核心边界**：本 Skill 是**通用**的。它接受**任意**概念名作为主题，不会把"Agent / Context / Skill"这几个具体词写死在提示词里。

---

## 2. 输入信息（启动 Skill 时必须澄清）

启动后**先**向用户确认以下 6 项，再开始任何正文写作：

| # | 字段 | 类型 / 选项 | 必填 | 默认值 |
|---|------|------------|------|--------|
| 1 | **目标概念** | 字符串 | ✅ | 用户原始输入 |
| 2 | **学习者背景** | 枚举：初学者 / 中级 / 资深 | ✅ | _（必问）_ |
| 3 | **学习深度** | 枚举：科普 / 工程应用 / 学术研究 | ✅ | _（必问）_ |
| 4 | **输出语言** | 枚举：中文 / 英文 | ⚠️ | 中文 |
| 5 | **输出格式** | 枚举：Markdown / HTML / 纯文本 | ⚠️ | Markdown |
| 6 | **落盘位置** | 路径字符串 | ⚠️ | `learning-materials/<concept-slug>.md` |

> 关键：**没有背景与深度，AI 永远会用同一档"半吊子科普"口吻写一切**。这两项不澄清视为不合格执行。

`<concept-slug>` 的命名约定：英文小写、用 `-` 替代空格、去掉标点。例：Transformer → `transformer`，大模型的上下文 → `llm-context`。

---

## 3. 生成步骤（七步，按序执行，不许跳步）

### Step 1 ── 澄清请求
- 按 §2 的 6 项逐一向用户确认。
- 必要时追加："这篇资料读完大概 15 分钟，你接受吗？"（避免目标过大或过小）

### Step 2 ── 检索权威来源（**硬性环节**）
- 至少调用 1 次 `WebSearch`、每个候选 URL 至少调用 1 次 `WebFetch` 抓取。
- 至少 3 类来源：百科 / 官方文档 / 学术或权威。
- **禁止编造**任何 URL、书名、作者、年份、论文标题。

### Step 3 ── 起草七段式学习包（顺序固定）
- 输出结构见 §4。

### Step 4 ── 真实性核查（交付前必做）
- 逐条访问参考 URL，验证可达 + 支撑正文。
- 在文末写明"参考来源核查日期：YYYY-MM-DD"。

### Step 5 ── 去 AI 痕迹审查
- 对照 `references/deai-checklist.md` 逐条勾。

### Step 6 ── 输出与归档
- 写入 `learning-materials/<slug>.md`。
- 同步更新 `learning-materials/INDEX.md`。
- 用户没要求 push 时**不主动** push。

### Step 7 ── 收集反馈
- 问用户哪段最有用 / 哪段最空泛。
- 反馈写入文件末尾的"修订记录"区。

---

## 4. 输出结构（七段式，顺序固定）

任何用本 Skill 产出的文件都包含以下 7 段。**不要打乱顺序**。

```
1. 学习目标      — 3–5 条，动词开头，对应布鲁姆分类法
2. 核心问题      — 3–5 个，从"是什么"递进到"何时不用"
3. 结构化解释    — 前置知识 → 核心定义 → 关键机制 → 形式化（可选）
4. 应用案例      — ≥2 个（其中至少 1 个"踩坑 / 反面"案例）
5. 概念辨析      — ≥1 张对比表，与 1 个最易混淆的概念对比
6. 自测题        — 5–8 题，含答案（默认折叠），覆盖至少 3 个认知层级
7. 参考来源      — 真实可访问 URL 列表 + 检索日期 + 核查日期
```

**完整字段**见 `references/template.md`。

**强制质量门**：
- 任何事实陈述必须带 `[n]` 编号，对应第 7 段的某条来源。
- 任何用 AI 直觉写出而查不到来源的内容，要么删，要么标"未找到公开来源，仅基于常识"。

---

## 5. 资料来源要求（硬性规则）

### 5.1 来源数量

- 每份资料至少 **3 个**独立来源。
- 至少包含 1 个**一手来源**（官方文档 / Wikipedia / 学术论文 / 经典教材），不允许 3 个来源全是二手博客。

### 5.2 来源类型优先级

不同学科的可信来源类型见 `references/source-types.md`。**默认优先级**：

1. 官方文档 / RFC / 标准
2. 主流教材 / 综述论文
3. 维基百科 / 百科全书
4. 主流期刊 / 学术会议
5. 技术博客（仅作为补充，不作为唯一来源）

### 5.3 引用格式

每条来源用 `[n]` 编号 + 表格形式列出，必含字段：

| # | 来源 | URL | 检索日期 | 在正文中支撑的事实 |
|---|------|-----|----------|-------------------|
| [1] | {{作者/机构}}《{{标题}}》{{年份}} | https://{{...}} | YYYY-MM-DD | {{...}} |

### 5.4 禁止行为（红线）

| 红线 | 例 |
|------|----|
| ❌ 伪造 URL / 论文 / 作者 / 年份 | 凭印象写"Vaswani 2017 的某篇论文" |
| ❌ 整段照搬 AI 训练数据 | 直接背出 Wikipedia 第一段 |
| ❌ 模糊归因 | "研究表明..."、"某权威机构指出..." |
| ❌ 凑数留死链 | 引用一条 404 URL 应付交差 |
| ❌ 用 Medium / 个人博客作唯一来源 | 中等可信度仅作补充 |

---

## 6. 自检要求（交付前必走）

按下面 4 步走完，**任何一步不过**则视为未完成：

### 6.1 真假检查

- [ ] 每个 `[n]` 引用的 URL 实际访问过（用 `WebFetch` 或 `curl`）
- [ ] 每个 URL 在交付时**仍然可达**（200/2xx，不是 404）
- [ ] 页面内容**真的支持**正文中的事实（不是张冠李戴）
- [ ] 没有凭空出现的论文、作者、年份、出版社

### 6.2 结构检查

- [ ] 7 段齐全，顺序正确
- [ ] 学习目标 ≥ 3 条，**每条以动词开头**
- [ ] 自测题 ≥ 5 题，**至少 3 个认知层级**
- [ ] 参考来源表**真实可访问**

### 6.3 去 AI 痕迹检查

对照 `references/deai-checklist.md`：

- [ ] 没有开场套话（"在当今时代"、"众所周知"…）
- [ ] 没有"作为一个 AI..."自我引用
- [ ] 没有"研究表明..."等模糊归因
- [ ] 没有堆砌无信息密度的三段式排比
- [ ] 没有每段都加 emoji 装饰
- [ ] 没有"如果还有问题请告诉我"式套话收尾

### 6.4 个人理解检查

- [ ] 至少 1 个**原创类比**（不是百科类比复述）
- [ ] 至少 1 个**原创对比表**（不是把别的资料里的表直接搬过来）
- [ ] 至少 1 个**踩坑 / 反面案例**（不是只讲成功路径）
- [ ] 至少 1 处**"何时不用"**的边界说明

### 6.5 核查签名

```
□ 已走完 6.1 真假检查
□ 已走完 6.2 结构检查
□ 已走完 6.3 去 AI 痕迹检查
□ 已走完 6.4 个人理解检查
□ 已在文末写明 "参考来源核查日期：YYYY-MM-DD"
□ 已更新 learning-materials/INDEX.md

核查人：{{...}}
核查日期：{{YYYY-MM-DD}}
```

## 硬性约束（违反 = 整篇重写）

| # | 约束 |
|---|------|
| ❌ | **禁止伪造**任何 URL、论文标题、作者、年份、出版社 |
| ❌ | **禁止整段照搬** AI 训练数据中的解释而不核查 |
| ❌ | **禁止**使用"研究表明"、"某权威"、"众所周知"等模糊归因 |
| ❌ | **禁止**只写"是什么"不写"为什么"和"什么时候不适用" |
| ✅ | **必须**为每个事实陈述标注来源编号 [1][2]… |
| ✅ | **必须**有学习目标（用动词开头） |
| ✅ | **必须**有自测题（不能只有讲解没有练习） |
| ✅ | **必须**有"核查日期"和"检索日期" |
| ✅ | **必须**体现作者个人理解（自绘类比、原创对比表） |
